# 0004 — `roles/dev-worker/prompt.md` describes the pipeline's tools instead of the objective

- Status: closed (M7, ADR 0020 §6): `ci/prompts.sh` in ci; `roles/dev-worker/prompt.md` rewritten under the rule; the re-record that validates it is M8's
- Labels: platform, roles/, M6 finding, owner decision, M7 (prompt work)
- Found: 2026-09-16, re-tuning the dev-worker budget after ADR 0018's run 3

## Problem

ADR 0018's run 3 finished ticket 0001's code at call 31, then spent
calls 34–43 running the mutation suite four times and was denied at the
budget with the PR text unwritten. M6's response was one more line in
`roles/dev-worker/prompt.md`: "do not run the mutation suite yourself".
That treats the symptom. The cause is that the prompt describes the
pipeline — it names the six gates ("risk scoring, a secret scan, a
dependency scan, SAST (bandit), the test suite, and mutation testing"),
`make`, `./go`, `tests/mutation/run.sh` — and a model told what will
judge it reasonably tries to run the judge. Every tool the prompt names
is an invitation; every tool it forbids is a second thing to keep in
sync with `gates/` and the Makefile, and the list will drift the day a
gate is added or renamed.

The rule to extract (owner decision, 2026-09-16): **`roles/*/prompt.md`
never names a gate, a gate's tool, or a Makefile target.** A prompt
states the objective and its acceptance — a change that satisfies the
ticket, proven by a test that would fail if the change were wrong — and
the pipeline judges it without being announced. The one command a
prompt may give is the one the role needs to do its work (for
dev-worker: how to run the app's tests from the checkout, ADR 0017 §10).

## Options seen so far

1. **Rewrite `dev-worker/prompt.md` under the rule** at M7, together
   with the first prompts for `architect` and `test-reviewer` (ADR 0019
   §8), then re-record ticket 0001 — the two `record`s that also fix
   the provisional budget in `roles/dev-worker/role.env`. The mutation
   line goes; if the model still runs the suite without being told it
   exists, that is a measurement worth having.
2. **A `ci` check that enforces it**: `ci/prompts.sh` NO-GOs when any
   `roles/*/prompt.md` contains a `gates/<name>` basename, a `GATES`
   entry from the Makefile, a `## `-listed target name, or the tool
   names the gates wrap (bandit, osv-scanner, gitleaks, cosmic-ray). A
   list to keep true, but one derived from the Makefile and `gates/`,
   not written by hand. Cheap; catches the drift the rule exists for.
3. Both: the rewrite proves the rule is workable on a real run, the
   check keeps it.

## Acceptance criteria

Given `roles/dev-worker/prompt.md` after the rewrite
When it is read against `gates/*.sh` basenames, the Makefile's target
names and the tools those gates run
Then none of them appears in it, and the only command it gives is the
one that runs the app's own tests.

Given a `./go record TICKET=0001 PROFILE=l1` under the rewritten prompt
When the run finishes
Then the transcript shows no call to the mutation suite, and the run
reaches its final message — or, if it does not, the reason is recorded
in HANDOFF as a measurement, not patched back into the prompt as a
new prohibition.

Given a later edit that puts a gate's name into any `roles/*/prompt.md`
When `./go ci` runs
Then it NO-GOs naming the file and the word (option 2 or 3).
