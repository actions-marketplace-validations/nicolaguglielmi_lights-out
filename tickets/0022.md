## Problem

In Postgres's `pg_stat_activity` the app's sessions cannot be told from
the migrations' or the tests': every connection is anonymous.

This ticket is one of the three `./go demo-mainline` runs together with
0020 and 0021. After it is judged, a person's change to
`meetups/db.py` lands on main through the code host, with no ticket: main
moves under this ticket's perimeter, so it does not merge on its old
judgment and goes back to rework on the new base.

## Acceptance criteria

Given the app
When `get_db()` opens a connection
Then the connection's `application_name` is `meetups`.

Given that change
When the test suite runs (`./go test`)
Then every existing test still passes.

## Perimeter

- `app/backend/meetups/db.py`
