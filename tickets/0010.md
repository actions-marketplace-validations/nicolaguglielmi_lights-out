# 0010 — Smaller hardening items from the pre-launch audit

- Status: open
- Labels: platform, hardening
- Found: 2026-11-02, audit before the public launch

## Problem

Each item was read in the code; none breaks `./go demo` today.

1. `adapters/gitea/merge.sh` merges whatever head the PR has now, not the
   head CI judged. A force-push between the ci and merge steps merges an
   unjudged commit; `./go audit` notices only afterwards. Gitea's merge API
   takes `head_commit_id`; the CodeHost port's `merge.sh` needs the head as
   an argument. **Done** in 293f114 (ADR 0019 amended 2026-11-02).
2. `core/launchpad.sh` treats an unanswered `release-freeze` as "not
   frozen" (stated in ADR 0030 §5). With flagd down, a freeze that is on is
   ignored. Decide whether no answer should refuse the release.
3. `ci/evals.sh` runs `adk eval ... || true` per evalset and greps one
   shared log per role: with two evalsets, one crash can hide behind the
   other's summary (latent: one evalset per role today). **Done** in
   51a25a2.
4. `ci/tower.sh` has bare commands under `set -e` in its later cases: a
   failure exits with no contract line.
5. `ci/contract.sh` counts lines after `$(...)` strips trailing newlines: a
   gate printing a blank line after its verdict passes. **Done** in
   0074fd8.
6. `./go demo` measures its 900 s budget from before the workbench build
   and the first image pulls, so a slow first download ends in NO-GO after
   every stage passed. Decide whether a local run should report the time
   instead of failing on it.
7. GitHub's `launch` job sometimes finds envoy-canary unanswered after
   180 s (runs 41424697447 and 41430855830), while `engine-compat` and
   `seam` start the same plane fine and other `launch` runs pass. Since
   2026-11-02 the job prints envoy's and the backend's logs; read them on
   the next failure. A guess to check: envoy starts once the backend
   container has started, not once it answers (`STRICT_DNS` clusters).
