# 0009 — A failed tower step leaves the ticket with no way forward but a reset

- Status: closed (2026-11-02, f00ee2f, ADR 0034): a failed step appends an `error` history entry; `./go resume TICKET=<id>` requests that step again; `ci/tower.sh` cases (e), (g), (g')
- Labels: platform, core/tower.sh, orchestrator
- Found: 2026-11-02, audit of core/ before the public launch

## Problem

When a step fails (a transient Gitea error in `status.sh`, a store read that
fails, a review harness error), `core/tower.sh` records the failure and the
`inproc` orchestrator acknowledges the message. The document stays in the
step's starting state with nothing queued. The only way to continue is
`tower.sh open`, which wipes the history the audit chain is built from.

## Acceptance criteria

Given a ticket whose last step failed and whose state is S
When the operator runs a resume command for that ticket
Then the step for state S is published again, the history keeps the failed
attempt and the new one, and `./go audit` still rebuilds the chain.

## Perimeter

- `core/tower.sh`
- `adapters/inproc/run.sh`
- `Makefile` (one new target)
- `ci/tower.sh`
