# 0003 — `record` accepts a fixture whose diff leaves the ticket's perimeter

- Status: open
- Labels: platform, core/, Makefile (`record`), fixtures/, M5 finding, candidate for M6
- Found: 2026-09-16, re-running ticket 0001 at L1 for ADR 0018's eval

## Problem

`fixtures/0001/dev-worker/patch`, the one fixture recorded at M5 and
replayed by `./go demo-crew` ever since, contains a hunk nobody asked for:
two lines in `app/backend/tests/conftest.py` that make the flags-file
lookup fall back to the source-checkout layout
(`parent.parent.parent / "flags"`). Ticket 0001 names four files (the
geocoder client, the fake or its contract, a test, one line of docs);
`conftest.py` is not one of them. The model made the change because the
backend test suite is written for the test image's layout and does not
run from a checkout — a harness gap, fixed in ADR 0018's session by
preparing the workspace in `core/crew.sh` — and nothing between the run
and the commit of the fixture checked that the diff stayed inside the
ticket's perimeter. Six gates judged it GO, correctly: none of them asks
that question.

Not a fault of that run or of the model: `record` has no notion of
perimeter. It records whatever passes the gates.

## Options seen so far

1. **A perimeter gate**: the ticket declares the paths it may touch (a
   `## Perimeter` section, or derived from the four-file list the ticket
   already implies) and `gates/` — or `record` alone — fails a diff that
   touches anything else. Cheapest; puts the declaration where the work
   is specified, which is where the plan's own tests-from-the-spec rule
   would put it. Against: a ticket that forgets to declare a path it
   legitimately needs blocks a correct PR; the declaration is a second
   thing to keep true.
2. **Risk-score it** (`policy/merge.env`, ADR 0016): out-of-perimeter
   paths raise the score to "second review" instead of failing. Softer,
   fits the existing mechanism, but at L0 nobody performs the second
   review, so a fixture would still be recorded.
3. **A `record`-only check**, not a gate: the fixture is a permanent
   artefact, a PR is not; only the fixture needs the stricter rule.
   Against: the demo's own PRs would carry the same drift unchecked.

## Acceptance criteria

Given a run of ticket 0001 whose diff includes `app/backend/tests/conftest.py`
When `./go record TICKET=0001 PROFILE=l1` judges it
Then the fixture is not written, and the reason names the file outside
the ticket's perimeter.

Given the recorded fixture `fixtures/0001/dev-worker/patch`
When `./go demo-crew` replays it at L0
Then the same check runs on the replayed PR and reports the same verdict
the recording did — a fixture never passes a rule its recording did not.
