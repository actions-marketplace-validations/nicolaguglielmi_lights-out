# M21 — GitHub as code host, release of an attached repository (plan)

- Milestone: plan §16 M21, steps in `docs/plans/third-arc-execution.md`.
- Decision record: [ADR 0043](../adr/0043-github-code-host-and-attached-release.md).
- Written 2026-11-04 by the M21 cloud session. The owner asked for no plan-mode
  wait: this file is committed, then the build starts.

## Frame

- **Deliverables.** `adapters/github/` with the eight CodeHost verbs plus
  `ready.sh`, `env.sh` and a git credential helper; the token from `.env`,
  never in argv, a `.git/config` or a harness container. The release step
  builds, signs and verifies an attached repository's merge itself. A cold
  `./go ci` check of the adapters' contract, a live conformance suite run
  on Gitea on every push, and a nightly against GitHub that skips with a
  clear notice while its repository variable is unset.
- **Acceptance, as commands.** On GitHub Actions for this branch: `ci`
  (`./go ci`, now with `codehost`), `engine-compat` (`./go demo`) and
  `gates` (`./go demo-gates`) green; `launch` runs `./go
  codehost-conformance` against Gitea. The owner's run, documented, not
  run here: `./go attach <clone> && ./go e2e CODE_HOST=github PROFILE=l1`.
- **Out of scope.** Retiring the Gitea `image` job for the bundled app;
  GitHub Enterprise; check runs; a GitHub App; any recorded or fake GitHub.

## Proof

No container engine was expected in the cloud session; docker turned out to
start here, but image builds need the session proxy's CA, so `./go ci` runs
locally on a workbench built with that CA added (scratchpad only) and every
engine proof is taken from GitHub Actions on the branch.
