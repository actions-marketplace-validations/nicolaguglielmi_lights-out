## Frame

**Deliverables.** An image of the workbench with lights-out inside, built by
a workflow; a POSIX `lights-out` wrapper (podman or docker) that runs
`init`, `gates`, `triage`, `postmortem` and `doctor` on any repository
without a clone of lights-out; `./go doctor`; a composite GitHub Action
that posts the `GO`/`NO-GO` line of `lights-out gates` as a check; hook
recipes for Claude Code, Codex and Gemini CLI that run `lights-out gates`
before a commit.

**Acceptance, as commands.**

- `./go demo-package` (GitHub Actions, job `package`, docker): builds the
  image, copies `workloads/minimal` into a fresh repository outside the
  checkout, `lights-out init`, commits the draft, `lights-out gates` →
  `GO`, init plus gates under 300 s.
- The workflow's `action` job: `uses: ./action` on a scratch repository
  built the same way, once on a good commit (`GO`, check run `success`)
  and once on a commit that fails a gate (`NO-GO`, check run `failure`).
- `./go ci` gains `ci/package.sh`; the `ci`, `engine-compat` and `gates`
  jobs stay green.

**Out of scope.** Publishing (no tag, no dispatch, the package stays
private: the owner's first publish); the plane through the wrapper (it
stays `git clone && ./go demo`); the engine socket inside the published
image; a recorded triage or post mortem of a user's alert (L1 with a key).
